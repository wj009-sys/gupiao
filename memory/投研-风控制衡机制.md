# 风控制衡机制

## 双轨制架构

操盘手（Agent6）与风控官（Agent3）构成「提案-审查」双轨制：

```
操盘手 → 制定交易计划 → 风控官审查
                            ↓
                     🟢批准 → 正常执行
                     🟡有条件 → 按条件修改
                     🔴否决 → 进入观察池
                     🔴分歧 → 上报投资领导仲裁
                               ↓
                          Agent7 最终裁定
```

## 各角色变化

### Agent3 风控官（新增能力）
- 审查操盘手的买入/卖出清单，逐项给出风控意见
- 独立给出持仓加减仓建议（不吃操盘手影响）
- 输出冲突项汇总，供投资领导仲裁
- `risk_check.py` 新增 `--trade-plan` 参数

### Agent6 操盘手（新增责任）
- 交易计划只是"建议"，需风控审查通过
- 收到有条件/否决后应修改计划
- 不得与风控官直接争论，分歧交领导仲裁

### Agent7 投资领导（新增仲裁职责）
- 读取风控报告的 `trade_conflicts` 结构化数据
- 逐项仲裁风控vs操盘分歧
- 结论写入最终决策报告

## 仲裁规则

| 场景 | 默认裁决 |
|------|---------|
| 风控 HIGH + 操盘买入 | 风控一票否决 |
| 风控否决买入（仓位/止损/行业原因） | 采纳风控 |
| 风控部分止盈 vs 操盘继续持有 | 折中：部分止盈1/3 |
| 风控减仓 vs 操盘持有（接近止损） | 采纳风控 |
